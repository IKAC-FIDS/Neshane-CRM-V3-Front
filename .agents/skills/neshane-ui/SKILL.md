# Neshane UI

Apply to visible components, layout, styling, interaction, accessibility, or forms. Read `../../../AGENTS.md`, `../../../architecture/governance-baseline.md`, `../../../architecture/standards/component-design.md`, and `../../../architecture/standards/styling.md`. Inspect existing tokens/components before adding new ones. Prefer semantic tokens, meaningful variants, named metrics, clear UI states, keyboard/focus support, responsive task priority, and first-class RTL/Persian behavior. Keep user-facing language clear and diagnostics secondary. Do not choose a component/styling framework without approval or build speculative generic components.

Deliver focused UI/source changes, relevant unexecuted component/accessibility/RTL tests, and unresolved design decisions. Never install dependencies or run builds, tests, applications, screenshots, containers, or deployments under repository policy.
