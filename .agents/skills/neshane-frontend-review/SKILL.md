# Neshane frontend review

Apply for frontend implementation or completion review. Read `../../../AGENTS.md`, the local baseline, and standards matching changed files. Inspect narrowly. Check Task scope, logical feature isolation/cycles, shared Design System ownership, absence of unapproved Micro-Frontend coupling, Backend implementation coupling, DTO/model separation, server/local/session state, contract-first compatibility/coexistence/deprecation, cancellation, domain-owned Backend authorization, tenant/session security, browser secrets, responsive RTL/accessibility/forms/states, risk-based test source, and evidence-backed readiness claims.

Report findings by severity with precise locations, followed by open decisions and unverified assumptions. If no findings exist, say so with limitations. When actual approved/configured tooling exists, follow `AGENTS.md` and run the relevant build, test, accessibility, screenshot and isolated application/container checks needed for evidence. Never infer production deployment, publishing, CI/CD, Git push, risk acceptance or Security Sign-off.
